# ДокРевью

Локальный инструмент для автоматической проверки Markdown/Diplodoc-документации.

ДокРевью помогает находить технические и редакторские проблемы в документации до передачи материалов на ревью. Проверку можно запускать в desktop-приложении или непосредственно в Visual Studio Code.

## Безопасность

Проверяемый проект используется строго в режиме **read-only**.

ДокРевью не создает, не изменяет, не переименовывает и не удаляет файлы или каталоги внутри выбранного проекта. Все правила и настройки проверки хранятся внутри ДокРевью.

## Возможности

### Проверка документации

ДокРевью поддерживает:

- выбор любого локального проекта;
- автоматическое определение каталога `docs/ru`, если он существует;
- выбор другой папки документации внутри проекта, например `documentation/manual`;
- запрет анализа папки за пределами выбранного проекта;
- проверку Markdown-файлов выбранной документации;
- фильтрацию результатов по файлу, уровню и категории;
- отображение всех проверенных Markdown-файлов, в том числе файлов без замечаний.

Замечания разделены по уровням:

- **Ошибка**;
- **Предупреждение**;
- **Информация**.

Замечания распределены по категориям:

- **Структура**;
- **Стиль**;
- **Терминология**;
- **Markdown**;
- **Ссылки**.

### Проверки

ДокРевью обнаруживает:

- битые локальные ссылки;
- ссылки на несуществующие якоря;
- дублирующиеся явные якоря;
- пустые ссылки;
- пустые якоря;
- нежелательные формулировки;
- пропущенные уровни заголовков;
- повтор слов;
- пробелы перед знаками препинания;
- несколько пробелов подряд;
- смешение кириллицы и латиницы;
- повторяющийся контент.

#### Повторяющийся контент

ДокРевью ищет одинаковые фрагменты длиной от 100 символов:

- в разных Markdown-файлах;
- в пределах одного Markdown-файла;
- в обычном тексте;
- в списках;
- в блоках кода.

При обнаружении повторяющегося контента ДокРевью показывает все найденные вхождения.

Рекомендуется проверить, является ли дублирование ошибкой. Если один и тот же контент намеренно используется в нескольких местах документации, его можно вынести в include.

> Правило проверки списка без вводного текста временно отключено.

## Работа с результатами

Для каждого замечания отображаются:

- файл и строка;
- уровень;
- категория;
- описание проблемы;
- фрагмент документа;
- рекомендация;
- идентификатор правила.

В desktop-приложении результаты проверки можно фильтровать:

- по файлу;
- по уровню;
- по категории.

В фильтре файлов отображаются все проверенные Markdown-файлы, включая файлы, в которых замечаний не найдено.

При выборе файла счетчики замечаний пересчитываются только для этого файла.

## Расширение для Visual Studio Code

ДокРевью можно использовать непосредственно в Visual Studio Code.

Desktop-приложение и расширение Visual Studio Code используют общий движок проверки.

Расширение поддерживает:

- проверку всей документации;
- проверку текущего Markdown-файла;
- автоматическое определение каталога `docs/ru`;
- выбор другой папки документации внутри проекта;
- отображение замечаний в панели **Problems**;
- переход из замечания к соответствующей строке Markdown-файла.

### Проверка документации

Чтобы проверить документацию проекта:

1. Откройте проект в Visual Studio Code.
1. Откройте палитру команд с помощью `Ctrl+Shift+P`.
1. Выполните команду:

   ```text
   ДокРевью: Проверить документацию
   ```

Результаты проверки появятся в панели **Problems**.

### Проверка текущего файла

Чтобы проверить только открытый Markdown-файл:

1. Откройте нужный `.md`-файл.
1. Откройте палитру команд с помощью `Ctrl+Shift+P`.
1. Выполните команду:

   ```text
   ДокРевью: Проверить текущий файл
   ```

Если файл содержит несохраненные изменения, сначала сохраните его.

### Выбор папки документации

По умолчанию ДокРевью пытается определить каталог `docs/ru`.

Чтобы выбрать другую папку документации:

1. Откройте палитру команд с помощью `Ctrl+Shift+P`.
1. Выполните команду:

   ```text
   ДокРевью: Выбрать папку документации
   ```

Папка должна находиться внутри открытого проекта.

## Запуск desktop-приложения

### Требования

Для разработки рекомендуется использовать Node.js 22 LTS.

### Установка зависимостей

```bash
npm install
```

### Запуск

```bash
npm run reviewer:dev
```

## Тесты

Чтобы запустить тесты:

```bash
npm run reviewer:test
```

## Production-сборка

Чтобы собрать desktop-приложение:

```bash
npm run reviewer:build
```

## Сборка расширения Visual Studio Code

Чтобы собрать расширение:

```bash
npm run reviewer:vscode:build
```

## Структура проекта

Основные компоненты ДокРевью:

```text
src/
├── engine/          # общий движок проверки
├── main/            # Electron main process
├── preload/         # Electron preload
├── renderer/        # интерфейс desktop-приложения
└── shared/          # общие типы и компоненты

extensions/
└── vscode/          # расширение Visual Studio Code

tests/
├── engine/          # тесты движка и правил
├── renderer/        # тесты интерфейса
└── vscode/          # тесты интеграции с VS Code
```

Desktop-приложение и расширение Visual Studio Code используют один движок из `src/engine`.

## Принцип работы

ДокРевью работает локально:

1. Пользователь выбирает проект и папку документации.
1. ДокРевью находит Markdown-файлы в выбранной папке.
1. Движок анализирует структуру и содержимое документов.
1. К документам применяются активные правила проверки.
1. Найденные замечания передаются в desktop-интерфейс или Visual Studio Code.

Исходные файлы документации при проверке не изменяются.
