# Настройка и запуск ДокРевью

Инструкция по установке, запуску и проверке ДокРевью.

Текущая стабильная версия — **v0.6.0**.

## Главное правило безопасности

Проверяемый проект используется только как источник данных.

ДокРевью не создает, не изменяет, не переименовывает и не удаляет файлы или каталоги внутри выбранного проекта.

Настройки и правила проверки находятся в самом ДокРевью. Добавлять `reviewer.config.json` или другие служебные файлы в проверяемый рабочий репозиторий не требуется.

Read-only режим дополнительно контролируется автоматическими тестами.

## Требования

Для разработки рекомендуется использовать:

- Node.js 22 LTS;
- npm;
- Git;
- Visual Studio Code — для разработки и запуска расширения VS Code.

Проверить установленные версии Node.js и npm можно командами:

```bash
node --version
npm --version
```

## Установка зависимостей

После клонирования репозитория перейдите в каталог проекта и выполните:

```bash
npm install
```

Если пакет Electron установился без бинарного файла, выполните:

```bash
node .\node_modules\electron\install.js
```

## Desktop-приложение

### Запуск

Для запуска ДокРевью в режиме разработки выполните:

```bash
npm run reviewer:dev
```

### Выбор документации

После запуска приложения:

1. Нажмите **Выбрать проект** и укажите корневой каталог локального проекта.
1. Если внутри проекта существует каталог `docs/ru`, ДокРевью предложит его автоматически.
1. При необходимости нажмите **Изменить папку** и выберите другой каталог документации внутри текущего проекта.
1. Нажмите **Проверить проект**.

Папку за пределами выбранного проекта использовать нельзя.

ДокРевью проверяет Markdown-файлы выбранного каталога и его вложенных каталогов.

### Работа с результатами

Результаты проверки можно фильтровать:

- по файлу;
- по уровню замечания;
- по категории.

В фильтре **Файл** отображаются все Markdown-файлы, вошедшие в проверку, в том числе файлы без замечаний.

При выборе конкретного файла список результатов и счетчики пересчитываются только для него.

Если в выбранном файле проблемы не обнаружены, ДокРевью сообщает, что замечаний нет.

## Расширение Visual Studio Code

Расширение находится в каталоге:

```text
extensions/vscode
```

Desktop-приложение и расширение VS Code используют общий движок проверки из `src/engine`.

### Сборка расширения

Выполните:

```bash
npm run reviewer:vscode:build
```

### Запуск расширения в режиме разработки

Откройте корневой каталог проекта ДокРевью в Visual Studio Code.

Нажмите `F5`.

Откроется отдельное окно **Extension Development Host**, в котором можно проверить работу расширения на тестовом или рабочем проекте.

Конфигурация запуска находится в:

```text
.vscode/launch.json
```

Путь `extensionDevelopmentPath` должен указывать на:

```text
${workspaceFolder}/extensions/vscode
```

### Проверка всей документации

В окне **Extension Development Host**:

1. Откройте проект с документацией.
1. Нажмите `Ctrl+Shift+P`.
1. Выполните команду:

   ```text
   ДокРевью: Проверить документацию
   ```

Замечания появятся в панели **Problems**.

Открыть панель можно с помощью `Ctrl+Shift+M`.

### Проверка текущего файла

Чтобы проверить только открытый Markdown-файл:

1. Откройте `.md`-файл.
1. Нажмите `Ctrl+Shift+P`.
1. Выполните команду:

   ```text
   ДокРевью: Проверить текущий файл
   ```

В панели **Problems** будут отображены результаты проверки текущего файла.

Если файл содержит несохраненные изменения, сначала сохраните его.

### Выбор папки документации

Если документация находится не в `docs/ru`, выполните команду:

```text
ДокРевью: Выбрать папку документации
```

Выбранный каталог должен находиться внутри открытого проекта.

## Тесты

Для запуска основного набора тестов выполните:

```bash
npm run reviewer:test
```

Тестами проверяются в том числе:

- парсинг Markdown;
- сканирование документации;
- определение корня проекта и документации;
- правила проверки;
- фильтрация результатов;
- работа с отдельными файлами;
- интеграция с Visual Studio Code;
- запрет записи в проверяемый проект.

Отдельные тесты контролируют read-only режим внешнего проекта:

```text
tests/engine/readOnlyExternalProject.test.ts
tests/engine/readOnlySourceGuard.test.ts
```

## Production-сборка desktop-приложения

Для проверки production-сборки выполните:

```bash
npm run reviewer:build
```

## Проверка перед фиксацией версии

Перед созданием коммита или релиза рекомендуется выполнить:

```bash
npm install
npm run reviewer:test
npm run reviewer:build
npm run reviewer:vscode:build
```

Все тесты и сборки должны завершиться без ошибок.

После этого проверьте состояние репозитория:

### `src/engine`

Общий движок ДокРевью.

Содержит:

- сканирование Markdown-файлов;
- парсинг документов;
- правила проверки;
- формирование результатов;
- проверку путей проекта и документации.

Движок используется как desktop-приложением, так и расширением Visual Studio Code.

### `src/main`

Main process Electron и IPC-взаимодействие desktop-приложения.

### `src/preload`

Безопасный интерфейс взаимодействия renderer-процесса с Electron.

### `src/renderer`

Интерфейс desktop-приложения.

Здесь находятся список замечаний, подробная информация о проблеме и фильтры результатов.

### `extensions/vscode`

Расширение Visual Studio Code.

Оно использует общий движок ДокРевью и преобразует найденные замечания в Diagnostics VS Code.

### `tests`

Автоматические тесты движка, интерфейса и интеграции с Visual Studio Code.

## Правила проверки

Активные правила подключаются в:

```text
src/engine/rules/index.ts
```

Каждое замечание содержит:

- идентификатор правила;
- категорию;
- уровень;
- файл;
- строку;
- название;
- описание проблемы;
- исходный фрагмент;
- рекомендацию.

Для замечаний используются уровни:

- `error`;
- `warning`;
- `info`.

Категории:

- `structure`;
- `style`;
- `terminology`;
- `markdown`;
- `links`.

Правило проверки списка без вводного текста сохранено в исходном коде, но временно исключено из набора активных правил.

## Повторяющийся контент

Правило `duplicate-content` ищет одинаковые блоки длиной от 100 нормализованных символов.

Проверяются:

- обычные текстовые блоки;
- списки целиком;
- fenced-блоки кода.

Повторы ищутся как между разными файлами, так и внутри одного Markdown-файла.

Заголовки и конструкции подключения include не рассматриваются как повторяющийся контент.

Для каждого найденного вхождения создается информационное замечание.

Правило не изменяет документацию автоматически. Пользователь самостоятельно решает, является ли повторение ошибкой и следует ли вынести общий контент в include.

## Локальные ссылки

При проверке относительных локальных ссылок учитывается весь выбранный проект.

Ссылка может вести за пределы выбранного каталога документации, если целевой файл остается внутри корневого каталога проекта.

Например, ссылка из выбранной документации на:

```text
../RT_ClusterManager/Installation_RT_ClusterManager.md
```

не считается битой, если целевой файл существует внутри проекта.

Переход за пределы корневого каталога проекта не допускается.

## Read-only режим

Изменение файлов проверяемого проекта является нарушением основного требования ДокРевью.

При разработке новых правил или интеграций запрещено добавлять операции записи в проверяемый проект.

Для получения информации о документации используются только операции чтения и проверки существования файлов.

После изменений, затрагивающих движок или работу с файловой системой, необходимо запускать read-only тесты вместе с общим набором:

```bash
npm run reviewer:test
```
