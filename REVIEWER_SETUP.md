# Documentation Reviewer v0.3

## Главное правило безопасности

Проверяемый проект используется только как источник данных. Documentation Reviewer не создает, не изменяет, не переименовывает и не удаляет файлы или каталоги внутри выбранного проекта.

Настройки и правила находятся в самом приложении. Добавлять `reviewer.config.json` или другие служебные файлы в рабочий репозиторий не требуется.

## Выбор документации

1. Нажмите **Выбрать проект** и укажите корень локального проекта.
2. Если внутри проекта существует `docs/ru`, Reviewer предложит его автоматически.
3. Чтобы проверить другую папку, нажмите **Изменить** рядом с полем **Документация** и выберите каталог внутри текущего проекта.
4. Нажмите **Проверить проект**.

Папку за пределами выбранного проекта использовать нельзя. Reviewer проверяет только выбранный каталог и его вложенные Markdown-файлы.

## Установка

```powershell
npm install
```

Если пакет Electron установился без бинарника:

```powershell
node .\node_modules\electron\install.js
```

## Запуск

```powershell
npm run reviewer:dev
```

Команда сначала собирает актуальную локальную версию приложения, затем запускает Electron. Горячая перезагрузка пока отключена.

## Тесты

```powershell
npm run reviewer:test
```

В тестах проверяются стандартный `docs/ru`, нестандартный `documentation/manual`, запрет выбора папки вне проекта и read-only гарантия внешнего проекта.

## Production-сборка

```powershell
npm run reviewer:build
```


## Новые проверки v0.3

- **Список без вводного текста** — информация, категория **Структура**.
- **Пропущен уровень заголовка** — предупреждение, категория **Markdown**.
- **Повтор слова** — ошибка, категория **Стиль**.
- Существующая проверка нежелательных формулировок остается в категории **Стиль**.

Интерфейс позволяет одновременно фильтровать замечания по уровню и категории. Цвет не является единственным индикатором: текстовые метки уровней сохраняются.
